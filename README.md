# Ключи — интерактивный прототип

Статический прототип «Ключи», рабочая версия «Проект Тани». Требуется Node.js 22 и npm. Исходники автономны: соседние папки и локальные резервные копии для сборки не нужны.

Актуальная подготовка к GitHub: [PUBLISH.md](PUBLISH.md). Для проверки сборки и сценариев: `npm run check`. Архив исходников: `npm run export:github` (Python 3).

В приложение входят все сценарии поездки, «Найти», «Чаты», «Выгоды», профиль, избранные отели и уведомления. Каталог и операции работают на локальных демонстрационных данных; состояние сохраняется в браузере. Реальные платежи и бронирования не выполняются.

Ниже инструкции по запуску и исторические заметки разработки; текущие исходники имеют приоритет над описаниями ранних версий.

## Локальная сборка

```bash
npm ci
npm run build
npm test
```

Готовый сайт появится в каталоге `dist`.

## Локальный просмотр

```bash
npm run preview
```

После запуска откройте `http://localhost:4173`.

## Публикация на GitHub Pages

1. Создайте репозиторий и поместите содержимое этой папки в его корень.
2. В настройках репозитория откройте **Settings → Pages**.
3. В разделе **Build and deployment** выберите **GitHub Actions**.
4. Отправьте изменения в ветку `main`. Сценарий публикации запустится автоматически.

## Оформление из UI kit Арбаны — 29 сентября 2026

По прямому поручению пользователя к рабочей версии в папке «Проект Тани» применён UI kit Арбаны. Это по-прежнему базовый прототип «Ключей»: Maidens Hotel, номер 412, счёт 480 ₽, прежние экраны, данные, сценарии и переходы.

- Навигация: «Поездки / Найти / Чаты / Выгоды». Профиль доступен через аватар.
- Golos Text Variable и исходные токены Арбаны: `src/arbana/tokens.css`, локальные шрифты `src/arbana/assets/`.
- Визуальная адаптация: `src/arbana/adapter.css`; исходная палитра экранов преобразуется в токены сборщиком `scripts/arbana-theme.mjs`.
- SVG-иконки из UI kit: `src/arbana/icons.js`. Этот слой не меняет маршруты, обработчики действий или состояние приложения.
- Сохраняется светлая тема. На мобильных ширинах экран подстраивается под высоту viewport; прокрутка остаётся внутри экрана.
- Исходная разметка и сценарии `src/prototype.html` сохранены. Единственная правка маршрутизации — исправление оставшегося соответствия старого названия «Ассистент», чтобы ранее переименованный пункт «Чаты» открывал исходный раздел.

До изменений создана полная копия исходников и сборки. Точный путь записан в `design/migration-baseline.json`.

Сборка: `npm run build`. Проверка сохранения логики: `node scripts/verify-preservation.mjs`. Отчёт: `design/verification.json`. Проверка сравнивает все 67 исходных встроенных скриптов с сохранённой версией и допускает только указанное исправление названия в маршрутизации.

В браузере проверены ключ до успешного открытия, заказ еды с корзиной, поиск и детали отеля, отправка вопроса ассистенту, правила лояльности, доступ к профилю, добавление билета, отправка отзыва, маршрут и меню поделиться. Проверена мобильная ширина 375 px. Полный перебор всех сочетаний состояний не выполнялся; исходные демо-ограничения прототипа остаются.

`keys-github-pages/`, исходная Арбана и UI kit не изменялись. Публикация не выполнялась.

## Найти и Чаты из Арбаны — 29 сентября 2026

По следующему прямому запросу пользователя эти два раздела теперь используют исходные React-компоненты, reducer, провайдеры и локальный API Арбаны. Это функциональная миграция, которая заменяет прежние разделы поиска и ассистента; описание выше относится к предыдущему этапу визуальной адаптации.

Перенесены каталог, поиск по городу/отелю, даты и гости, фильтры и сортировка, фото и карта, карточки/номера/тарифы, избранное, цены, лента, друзья и совместные подборки, помощник с историей, бронирование/оплата/подтверждение, список чатов, новые диалоги, поиск, черновики, ответы и передача сотруднику. Фото, видео и шрифты локальны. Демо-ответы, оплаты и карта сохраняют ограничения автономной Арбаны.

- `vendor/arbana/` — зафиксированная копия источника и его сборщика, независимая от соседней папки Арбаны.
- `scripts/build-sections.mjs` — воспроизводимая сборка исходного приложения и проверяемые точечные адаптации интеграции.
- `src/sections/runtime-adapter.js` — контейнер экранов, связь с навигацией «Ключей» и контекст Maidens Hotel.
- `src/sections/host.js` — переключение разделов; один постоянный iframe сохраняет общее состояние поиска и чатов при переходах. Изоляция защищает CSS и обработчики базового прототипа от глобальных стилей React-приложения. Это локальная часть сборки, внешних сайтов и серверов она не требует.
- `src/sections/frame.css`, `host.css` — размеры экрана и мобильная прокрутка.
- `dist/sections/` — готовый автономный модуль. Публиковать/передавать нужно весь `dist`.

Главная, цифровой ключ 412, активное проживание Maidens Hotel, услуги, маршрут, выгоды и профиль остаются из проекта Тани. Из новой навигации «Поездки», «Выгоды» и аватар возвращают в исходные разделы. Чат Maidens получает правильные даты, гостя и сведения о завтраке. Ссылка на текущую бронь и обращение о проблеме открывают исходные сценарии Тани. Новая подтверждённая демо-бронь доступна карточкой на главной; она не подменяет текущее проживание.

Состояние поиска, диалогов и новой демо-брони сохраняется при переключении вкладок в рамках открытого прототипа. Как и в исходной Арбане, перезагрузка запускает сценарий заново; данные локального аккаунта, включая избранное, сохраняются. Для них используется отдельный ключ `keys-arbana-sections-v1`.

Проверки: `npm run build`, затем `npm test`. Оригинальные проверки: `node --test vendor/arbana/tests/prototype.test.mjs`. Проверка сохранности исходного прототипа продолжает сравнивать все его встроенные скрипты; отдельные тесты проверяют новые сценарии и связь с оболочкой. Резервная копия до переноса указана в `design/sections-migration.json`. Исходная Арбана и опубликованный сайт не изменялись.

## Веб-версия: до заезда и во время проживания

Переключатель «Десктоп / Мобильная» расположен рядом с выбором сценария. Первый веб-экран доступен по `?scenario=booked&arrivalDay=day-8&view=desktop`; поддержаны также `day-3` и `arrival`. Для проживания доступны `?scenario=stay&stayDay=day-1&view=desktop`, `day-2` и `checkout`. Сценарии без брони (`?scenario=search&view=desktop`) и после поездки (`?scenario=after&view=desktop`) также поддерживают десктоп.

`src/scenarios/desktop.js` и `desktop.css` адаптируют существующие карточки и действия: состояние брони и услуг общее для двух форматов. На десктопе нет отдельного меню разделов: поиск, поездка, чат с отелем, услуги, кошелёк лояльности и подборки доступны с главной. Фото и компактный таймлайн образуют единую карточку; ключевые действия по брони выделены плитками; за 3 дня и в день заезда к ним добавляется инструкция по заселению. Онлайн-регистрация доступна за 3 дня и в день заезда. Внутренние сценарии открываются в существующих окнах. Анализ Арбаны и границы переноса описаны в `design/desktop-prearrival-layout.json`, результаты проверки — в `design/desktop-prearrival-verification.json`.

Десктоп проживания использует исходные блоки номера, электронного ключа, депозита, завтрака и помощи; `src/scenarios/desktop-stay.css` задаёт их компоновку. В день выезда остаются поздний выезд, возврат депозита и памятка. Места рядом и общий кошелёк расположены справа, подборки — ниже. Переход на мобильный формат возвращает исходное расположение блоков; состояние услуг общее.

Для сценариев без брони и после поездки `src/scenarios/desktop-search-after.css` задаёт сетку с основной колонкой и боковым блоком баллов. Карточки поиска, проживания, документов, отзыва и приглашения друзей переиспользуются из мобильных сценариев; общий кошелёк и подборки перемещаются между сценариями без дублирования. Мобильный DOM-порядок восстанавливается при переключении формата.

Название отеля в десктопной шапке открывает контекстное меню поездки (`src/scenarios/desktop-trip-menu.js` и `.css`). Меню использует native popover: повторный клик, Escape и клик вне окна закрывают его. Даты до заезда берутся из текущей брони, заказы — из `KeysActiveServices.getOrders()`. Действия переиспользуют существующие экраны, а ключ и регистрация доступны только в соответствующих сценариях. Завершённая поездка предлагает документы и отзыв.

Десктопный профиль (`src/scenarios/desktop-profile.js` и `.css`) использует общую шапку и исходные мобильные компоненты. Фото, телефон и лояльность сгруппированы в боковой колонке, остальные данные — в смысловых карточках. При переходе в мобильный режим восстанавливается исходный порядок элементов. Документы и настройки открываются в центрированных окнах; кнопка назад сохраняет исходный раздел.

### Десктоп: уведомления и бонусная программа

`src/scenarios/desktop-account.js` и `.css` расширяют общий веб-каркас: одна шапка перемещается между главной, профилем, бонусной программой и уведомлениями. Баллы в шапке, карточка лояльности на главной и в профиле открывают бонусную программу. Кнопка назад восстанавливает исходный экран, включая профиль. Баланс, уровень, раскрытия правил, приглашение друзей и история начислений переиспользуются из мобильного раздела «Выгоды».

Уведомления остаются в общем React-модуле: `KeysBridge` получает формат просмотра и сообщает высоту контента родительской странице. Десктопный слой `src/sections/frame.css` меняет только компоновку ленты и настроек; сценарные уведомления, статусы прочтения и переходы к отзывам общие. При переключении на мобильный вид восстанавливается мобильное оформление. Анимация появления учитывает `prefers-reduced-motion`.

### Десктоп: «Найти»

`src/sections/desktop-find.css` адаптирует существующий React-поиск под веб-каркас: горизонтальная форма, история запросов, подбор по фото, тематические подборки и сетка просмотренных отелей. Выдача сохраняет встроенную карту 2ГИС, раскрытие карты и фильтры; карточки размещаются в сетке. Даты, гости, избранное, подбор по предпочтениям и карточки отелей используют существующие обработчики. Десктоп определяется сообщением родителя, мобильные стили не заменяются. Общая шапка подключается через `desktop-account.js`; уведомления, открытые из поиска, возвращают в тот же экран поиска.

### Вход по телефону — мобильный сценарий

`?scenario=guest&view=mobile` открывает «Гость не авторизован»: номер телефона → шестизначный код → имя → «Поездки» без бронирований. Проверочный код — `123456`; он указан над прототипом на шаге подтверждения. Реальная отправка СМС и серверная авторизация не подключены. Номер и имя живут только в памяти текущей вкладки, используются в приветствии и профиле; повторный выбор сценария сбрасывает вход. Исходные данные других демонстрационных сценариев восстанавливаются. В профиле после входа работает «Выйти из аккаунта».

Модель `src/scenarios/auth-model.mjs` проверяет номер, неверный и просроченный код, интервал повторного запроса (30 секунд) и имя. Управление формами и доступностью — `auth.js`, общие токены оформления — `auth.css`. Обычная регистрация в настоящем приложении потребует серверного подтверждения номера; фиксированный код предназначен только для прототипа.

### Закрытое приглашение для отельера

Отдельный сценарий `?scenario=guest-returning&view=mobile` — «Гость не авторизован, но зарегистрирован». Использует те же экраны телефона и шести цифр СМС-кода. После правильного кода `123456` сразу открывает главную без запроса имени; имя и аватар берутся из существующего профиля прототипа. Неверный или просроченный код не завершает вход. Для нового гостя и приглашённого отельера шаг имени сохраняется.

`?scenario=guest-invite&view=mobile` — сценарий «Отельер · по приглашению». Персональный инвайт TravelLine Partners Club действует ещё 6 дней. После принятия используются общие экраны номера, кода `123456` и имени. Далее: подтверждение статуса отельера → рабочая почта экстранета → ожидание решения → подтверждение или отказ.

`partner-invite.js` показывает отдельный вспомогательный ЛК TravelLine рядом с телефоном; на ширине до 850 px он размещается ниже, с переходом из приложения. Уведомление содержит введённый подтверждённый номер и email. «Подтвердить связывание» открывает статус отельера и сообщение о Friendly Rate; «Отклонить» оставляет тарифы заблокированными, разрешая повторить запрос или изменить почту. Старые запросы после изменения email/сценария недействительны. После успешного завершения статус остаётся на главной и в профиле до переключения сценария.

Это локальная демонстрация двух интерфейсов: реальные email, уведомления в TravelLine и проверка тарифов не отправляются и не выполняются. Модель состояний — `partner-model.mjs`; тесты — `tests/partner-invite.test.mjs`.

На вопросе «Вы работаете в отеле?» доступно «Пропустить»: пользователь входит без статуса отельера. На главной остаётся баннер «Откройте тарифы Friendly Rate», в профиле — «Подтвердить статус отельера». Оба входа продолжают верификацию без повторного СМС. Повторный пропуск возвращает на исходную страницу; после одобрения напоминание заменяется подтверждённым статусом. Пропуск сам по себе не открывает Friendly Rate.

Для сценария приглашения имя, телефон и итоговый статус сохраняются в `sessionStorage` текущей вкладки, чтобы баннер переживал перезагрузку. Выход из аккаунта или ручное переключение сценария удаляет эту демонстрационную сессию. Письма, СМС и запросы TravelLine по-прежнему не отправляются.

Экраны приглашения используют общие токены Keys: заголовки 28/34 medium, текст 14/21, подписи 12/18, поля 16/24 и контролы высотой 48 px. СМС-код вводится в шесть отдельных полей с автопереходом и вставкой целиком. Карточки: радиус 20 px, отступ 16 px; иконки контурные без подложки. Иллюстрация остаётся на приглашении, ввод телефона — компактная форма. Ожидание и рабочая почта объединены в одну карточку, подтверждение использует системный зелёный фон. Проверены ширины 320/375/1200 px, пропуск и продолжение, отказ и повторный запрос, одобрение и возврат в приложение.
