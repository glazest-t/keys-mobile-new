Этот пакет фиксирует текущую согласованную версию «Ключей» из «Проекта Тани». Он включает переносимые основы и композиции, точный снимок приложения, его стили и поведение. Для новой реализации можно выбрать любой frontend-фреймворк.

1. Начните здесь

  1. Прочитайте manifest.json, foundations.json и этот документ.
  2. Откройте 8 сценариев. Это визуальный источник истины для сложных экранов.
  3. Подключите tokens.css и key.css. Выберите нужную композицию из examples.json или templates.js.
  4. Перенесите HTML в компоненты своего фреймворка. Сохраните роли, геометрию, семантику и имена токенов.
  5. Свяжите props и события из components.json с данными из contracts.d.ts.
  6. Проверьте состояния, ширины 320 / 375 / 390 / 430, длинные строки, клавиатуру и reduced motion.
<link rel="stylesheet" href="tokens.css">
<link rel="stylesheet" href="key.css">
<body class="key-ui">
  <button class="k-button" type="button">Найти отель</button>
  <script src="data.js"></script>
  <script src="templates.js"></script>
  <script src="key.js"></script>
  <script>KeyUI.mount();</script>
</body>

Для статических компонентов достаточно двух CSS-файлов. data.js содержит реестр и SVG, templates.js — функции композиций. key.js добавляет демонстрационную интерактивность. Фреймворк может реализовать этот же контракт собственными компонентами; не подключайте два обработчика одного действия.

document.addEventListener('key:change', event => {
  const { component, type, value } = event.detail;
  // Router / application state / service adapter owns real effects.
});
KeyUI.mount();       // Идемпотентная установка; повторно измеряет новые табы.
KeyUI.toast('Услуга добавлена');
KeyUI.destroy();     // Удаление обработчиков и наблюдателей.

Запуск архива: python3 -m http.server 8780 из корня пакета → http://localhost:8780/. Интернет не нужен для основных компонентов и локальных изображений. Внешние карты и интеграции требуют подключения.

2. Приоритеты и границы пакета

СлойНазначение

components.json / contracts.d.tsКонтракты семейств: входы, состояния, события, правила.
key.css / templates.js / key.jsПереносимая нормализация компонентов и живые примеры. Не готовый backend приложения.

Если витринная композиция сокращает контент сложного экрана, не считайте это удалением функций. Полный состав и сценарий находятся в снимке. Новые примеры loading/error/offline и клавиатурное управление — дополнения переносимых примитивов. Они не меняют бизнес-логику оригинального прототипа.

3. Композиция и размеры

  • Белый фон приложения, расстояние между основными блоками 16 px. Карточка radius 20, padding 16; внутри 8–12 px. Ниже 360 px допустимы горизонтальные 12 px в карточке.
  • Корневой заголовок 28/34/500. Вложенный экран и bottom sheet — 20/26/500. Заголовок блока — 17/24/500. Основной текст 14/21/400, действие 14/21/500; подпись 12/18.
  • Выбор значения: нативный select в .k-select, контурный chevron 20 px справа с отступом 12 px. Под значение зарезервировано 44 px справа; иконка не перехватывает нажатие.
  • Поля всегда 16/24/400. Не уменьшайте их ради компактности. Валидируйте рядом с полем; label остаётся видимым.
  • Кнопка 48 px minimum, radius 14. Действие футера 44 px. Действие услуги 36 px внутри кликабельной строки ≥76 px. Не уменьшайте размер шрифта при нехватке места — дайте перенестись тексту.
  • Табы: фон soft, padding 4, radius 14, item ≥42, radius 10, текст 14/21/500. Активное состояние меняет фон/цвет, не вес. На 320–359 px горизонтальный padding item 4 px.
  • Иконка строки 22 px в слоте 24 px, без фона/обводки/тени. Иконка кнопки 20, навигации 24, ссылки 14. Stroke 1.65, round. Кнопки, аватары и статусы не являются декоративными иконками.
  • Шапка второстепенного экрана: назад 44 × 44 и заголовок. Не повторять название отеля под заголовком. Профиль — вложенный экран.
  • Нижнее меню: Поездки, Найти, Чаты, Выгоды. Трек 58 px, пункт 50 px. Safe area снизу, отступ контента минимум 88 px. На вложенных страницах навигация не дублируется.
  • Изображения резервируют высоту и имеют alt. Предпочтительна широкая галерея, текст ниже. Без нескольких вложенных обводок. Карточка отеля: цена справа сверху, базовая цена/скидка ниже; рейтинг отдельно.

Точные образцы

В rendered-reference/ сохранены 8 экранов сценариев и ключевые компоненты, снятые прямо с текущего прототипа. index.json содержит оригинальную DOM-разметку и computed styles каждого видимого элемента: шрифты, цвет, размеры, отступы, границы, переходы. Это дополнительная опора для точного переноса сложных карточек. В витрине они открываются через «Точный вид в текущем прототипе».

Роли цвета

Brand — действие и навигация. Positive — успешный исход, включённость, оценка и выгода. Warning — ожидание/внимание. Danger — ошибка/удаление. Не передавайте статус только цветом. Белый текст применяется на brand и тёмных фото-поверхностях, но не на soft. Скидка и рейтинг — разные сущности.

Responsive

Продукт строится сначала для 375–390 px и проверяется от 320 px. Не используйте жёсткую ширину карточки или фиксированную высоту текста. Галереи и чипы могут скроллиться внутри своей области; страница не должна прокручиваться по горизонтали. При увеличении текста до 200% сетки и кнопки могут переноситься. Каталог кита имеет собственный desktop layout и не задаёт размеры экранов приложения.

4. Состояния и переходы

СемействоОбязательная логика
НавигацияХранить origin с экраном, query, scroll и focus. Назад из профиля/уведомлений возвращает именно туда. Смена сценария отменяет незавершённые анимации, но не должна смешивать данные бронирований.
Услугаavailable → requested → approved → in-progress → completed; отмена/ошибка отдельно. Included не равно added. При добавлении/удалении возврат на origin + toast. Добавленная платная услуга явно подписана; действие Изменить. На детали один актуальный CTA.
Ранний / поздний заездОдин паттерн выбора времени, запроса, подтверждения и удаления во всех точках входа. Ожидание ответа отеля не равно успешному оказанию или списанию денег.
СчётРазделять внесённый депозит, проведённые расходы, доступный остаток. Pending request не создаёт расход. Денежные значения хранить в копейках, отображать Intl.NumberFormat.
Броньconfirmed не равно paid. Подтверждение рядом с номером брони, paid/partial рядом с оплатой. Изменение: ввод → новые условия → подтверждение → главная + toast. Условия и цена требуют актуальной quote.
ДокументыВыбор: чек на проживание / подтверждение брони; отдельные скачивания + Сохранить все документы. Страница брони раскрыта полностью, без скрытой обязательной информации.
ОтзывыОценка → впечатления + фото → благодарность. Нет повторного отеля/дат и личного сообщения. Только после отправки 5 звёзд — предложение чаевых. Ошибка не очищает текст и фотографии.
УведомленияSearch: без опросов проживания. Stay day1: без первой ночи. Day2: первая ночь. Checkout/after: первая ночь и итоговый опрос. Отзыв новее входа в приложение; unread отдельно от наличия записи.
ПоискИстория хранит query, просмотренные — только отели. Избранное через сердце в шапке Найти; фильтры по городам избранных. Сохранить фильтры и выбранный отель при возврате из деталей.
Карта2ГИС везде, где карта. Collapsed 176 px → expanded, маркер показывает те же факты отеля, что список. Свайп вверх сворачивает; кнопка доступна как альтернатива жесту. Loader, ошибка, повтор и пустая выдача обязательны.
ShareПоездка: read/manage, одна кнопка Поделиться ссылкой. Управляющая ссылка требует реальных прав и токена. Отель: кнопки действий без сводки. Referral — отдельный смысл, общий компонент во всех разделах.
Профиль / чатФото загружается по нажатию аватара и синхронизируется во всех шапках. Вверху имя и телефон. Чат хранит draft, delivery state, unread; отправка не должна дублироваться.

Негативные и промежуточные состояния

Компонент остаётся узнаваемым при empty, loading, disabled, error, offline, partial-data. Loading удерживает размеры и блокирует повторную команду, но сохраняет доступную подпись. Ошибка описывает проблему и даёт повтор/исправление. Пустота объясняет следующий шаг. Недоступное системное разрешение не маскируется успешным состоянием.

5. Анимации и переходы

motion.json задаёт смысловые роли, исходник, длительность, easing и reduced-motion. motion.inventory.json сохраняет все найденные декларации и фрагменты JS. Точные keyframes также собраны в keyframes.json со ссылками на исходники. Витрина движения показывает схему механики; точные составные движения проверяйте в компоненте и снимке.

  • Нижняя капсула: 380 ms cubic-bezier(.2,.8,.2,1); иконка 420 ms spring; press 80 ms, release 220 ms.
  • Табы: 300 ms cubic-bezier(.22,1,.36,1), положение и ширина индикатора измеряются по активному элементу.
  • Профиль: вход 280 ms, 40 px справа и opacity; выход 160 ms, 32 px вправо, затем возврат origin. Повторный Back во время выхода блокируется, старое движение отменяется.
  • Карта: высота 280 ms cubic-bezier(.2,.8,.2,1). Сообщение: 320 ms; toast: вход 340 / выход 200 ms.
  • Фоны/цвета/обводки: обычно 180 ms. Шторка переносимого кита нормализована до 300 ms ease-ios и радиуса 24; оригинальные варианты остаются в снимке.
  • Системное prefers-reduced-motion отключает перемещение, масштаб, bounce, shimmer и бесконечные пульсации. Логика, тексты и aria-live остаются. Нельзя ждать animationend, если анимация отключена.

6. Семантика и доступность

  • Действие — button, переход — a. Не вкладывать интерактивные элементы друг в друга. Для карточки с избранным используйте отдельные области ссылки и кнопки.
  • Табы: tablist/tab/tabpanel, aria-selected, roving tabindex; Left/Right, Home/End. Фильтры-кнопки — aria-pressed; настройки — checkbox/switch.
  • Поля: label, autocomplete, inputmode, aria-invalid и текст ошибки через aria-describedby. Checkbox/radio остаются нативными.
  • Bottom sheet: dialog, accessible title, фокус внутри, Escape/закрыть, возврат фокуса. После закрытия фон снова доступен. Не допускайте фокус на перекрытых элементах.
  • Цветовой контраст проверять для реальных пар и фото. В файле verification.json зафиксирована проверенная область; это не сертификат соответствия всего приложения WCAG.
  • Для кнопки-иконки — aria-label. Для SVG внутри подписанной кнопки — aria-hidden. Звёзды сообщают числовую оценку; status содержит текст.
  • Toast — role=status / aria-live=polite, не переводит фокус. Критическая ошибка доступна до исправления, а не исчезает за несколько секунд.

7. Данные, медиа и интеграции

Контракты TypeScript описывают необходимые сущности, а не готовый API сервера. Цены, баллы, даты, тарифы и SLA в прототипе примерные. Production-реализация требует источника бронирования, идемпотентных платежей, серверного подтверждения услуг, защищённой загрузки документов, доставки сообщений, push и цифрового замка.

Снимок использует оригинальную структуру хоста и встроенного модуля поиска/чатов. При переносе в единое приложение iframe не обязателен: сохраняйте пользовательское поведение, а не техническое наследие. Ключи карт, авторизация и URL управления поездкой должны поступать из конфигурации/сервера.

В assets/ находятся выбранные фотографии и локальные шрифты; полный набор медиа — в reference-app/. assets.json фиксирует источник. Включение в кит не создаёт новую лицензию на фотографии; права на публикацию проверяются по исходным материалам. Существующие license-файлы сохранены вместе со снимком.

8. Чек-лист реализации

  1. Все 8 сценариев соответствуют составу и условной логике в scenarios.json.
  2. Корневые разделы, вложенные страницы и Back сохраняют контекст.
  3. Типографика измерена по computed styles; вес 400/500, табы 14/21/500, поля 16.
  4. Повторяемые компоненты используют общие токены и один контракт; нет локальных произвольных отступов.
  5. Иконки без декоративных подложек; rating и discount семантически разделены.
  6. Проверены состояния формы, загрузки, ошибки, пустоты, partial payment и several service orders.
  7. Клавиатура, focus return, reduced motion и 320 px работают; CTA не перекрывает навигацию.
  8. Платёж, документ, карта и загрузка подключены к реальным адаптерам; демо-успех не заменяет ответ сервера.
